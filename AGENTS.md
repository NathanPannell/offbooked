# Offbooked

Remote line recording and run-through playback for theatre casts. A director uploads a script, shares one link per actor, each actor records their lines on their phone, and the server stitches everything into a lyrics-style run-through. The MVP backlog is in GitHub issues; #1 lists every credential and decision.

## Layout

- `backend/`: Node 24 + Fastify API and, later, the ffmpeg render worker. TypeScript runs through Node's type stripping, so there is no build step. `tsc` is for typechecking only.
- `web/`: the Vite + React app at offbooked.com (landing, director app, actor recording, run-through player, on-device accuracy check). See "Web" below.
- `railway.json`: Railway build and health check config for the backend.
- `.github/workflows/`: `ci.yml` (the CI gate, see "Delivery"), `deploy-backend.yml` (deploys `main` to Railway).

## Delivery

Every change ships the same way, through the `deliver` skill (`~/.claude/skills/deliver/SKILL.md`). There are no preview deployments.

1. Branch from the latest `origin/staging` (`feat/`, `fix/`, `chore/` or `ci/<name>`), in the session's worktree or `<workspace>/.claude/worktrees/<branch>/`. Scratch files (logs, screenshots, throwaway databases) go in `<workspace>/.claude/tmp/<branch>/`, outside the repository, and can be deleted freely.
2. Open a **draft** PR against `staging`.
3. CI (`ci.yml`) is the gate. It runs on every PR into `staging` or `main` and on each push to `staging` or `main`, with these jobs:
   - **Backend**: `npm ci`, Prettier, ESLint with zero warnings, `tsc`, migrations applied twice to a throwaway Postgres 17 service container (the second run must be a no-op), and the tests with a coverage floor (`test:coverage`, which includes the render worker's idle-no-queries test). In CI the DB tests must run: `src/test/helpers.ts` fails without `DATABASE_URL`.
   - **Web**: `npm ci`, Prettier, ESLint with zero warnings, `tsc`, Vitest with a coverage floor (`vite.config.ts`), and the production build.
   - **E2E**: the web app built against a local API, served by `vite preview`, with the real backend on a throwaway Postgres (`web/playwright.config.ts`). The journeys in `web/e2e/` run on desktop and phone Chromium: a director signs in, uploads a script and copies the cast link; a cast member opens it, skips the intro, picks a part and reaches their lines. The report and traces are uploaded when it fails.
   - **Docker**: builds the Railway image and checks Piper speaks inside it.
   - **Security**: `npm audit --audit-level=high` for both packages, no committed `.env` files, and a gitleaks scan of the full history.
4. Review the diff, fix blocking findings, mark the PR ready once every check is green on the head commit, and squash-merge into `staging`. Confirm CI passes for the merge commit on `staging`. Merging into `staging` deploys nothing.
5. Production is a separate PR from `staging` to `main`, made only when the user asks and merged only with their approval. A push to `main` deploys the backend (`deploy-backend.yml`) and the web app (Vercel).

GitHub rulesets and branch protection need a paid plan for this private repo, so nothing stops a red PR from merging: merge only when every check is green on the head commit. Coverage floors are today's levels; raise them when coverage rises, never lower them. The backend floor counts only modules a test imports (Node's coverage), so give every new module a test. The React Compiler lint rules are off in `web/eslint.config.js` because the app doesn't use the compiler; the classic hook rules are errors.

## Backend

- Contract: `docs/api.md`. Code: `src/routes/*` (HTTP), `src/parse/*` (file extraction, line labelling with Claude, cue repair, assembly), `src/render/*` (ffmpeg pipeline and in-process queue), `src/storage/*` (`local` or `s3`), `src/email/*` (Resend or log). SQL migrations live in `backend/migrations/NNN_name.sql` and run at startup.
- Scripts: `npm run dev` (loads `backend/.env`), `npm test` (DB tests run in a throwaway schema on `DATABASE_URL` and are skipped without it), `npm run typecheck`, `npm run seed` (demo director `director@example.test`, Hamlet 1.2, four actors, tone takes and a render; prints the sign-in link and invite URLs; `npm run seed -- --reset` archives the old demo and makes a new one).
- Env: `DATABASE_URL`, `SESSION_SECRET`, `INVITE_TOKEN_SECRET` (required); `APP_URL`, `API_URL` (base for local file URLs and the email unsubscribe link), `CORS_ORIGINS` (comma list, `*` matches one host label); `ANTHROPIC_API_KEY` (optional; without it the heuristic parser is used); `EMAIL_DRIVER` (`log` or `resend`, defaults to `resend` when `RESEND_API_KEY` is set), `RESEND_API_KEY`, `EMAIL_FROM`; `STORAGE_DRIVER` (`local` with `STORAGE_DIR`, or `s3` with `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`); `RENDER_DEBOUNCE_MS` (default 15000); `TTS_DRIVER` (`piper` by default, `off` disables TTS), `PIPER_BIN` and `PIPER_VOICES_DIR` (default `/opt/piper/piper` and `/opt/piper/voices`, as in the Docker image), `TTS_CONCURRENCY` (clips synthesized at once, default 2; Piper keeps up to `TTS_CONCURRENCY` + 2 processes, one model each, and each holds 100–300 MB), `TTS_CUE_WAIT_MS` (default 2500); `PORT`, `APP_REVISION`.
- Script parsing (`src/parse/`) uses Claude Haiku only (`PARSE_MODEL = "claude-haiku-5-5"`, effort `medium`, in `src/parse/label.ts`). Never switch to a larger model. The flow:
  1. `source.ts` reads PDF (`pdf.ts`: reading order, overprinted/fake-bold text, kerning splits, running headers), DOCX (via HTML, so soft line breaks in verse survive) or plain text (UTF-8/16, Windows-1252). `noise.ts` strips line numbers that run through the document (`FTLN 0001`, margin counters).
  2. `label.ts`: Haiku labels numbered line ranges of about 180 lines (speech + speaker + cue, continuation, direction, heading, not-part-of-the-play). It never re-types text. `pipeline.ts` keeps each valid prefix and re-asks from the first unlabelled line, up to four times, before the heuristic parser takes the rest.
  3. `cues.ts` learns the cues used across the whole script and repairs the model's blocks: re-splits merged speeches at cue lines, fixes shifted speakers, claims cue lines labelled as directions, and reclaims dialogue labelled as front matter after the play has started.
  4. `assemble.ts` builds lines from the source text: strips cues, keeps each speech as one dialogue line with directions printed inside it or on its cue line (`[brackets]`, `_italics_` sentences, parentheses in scripts that use them for directions, ones the model marks with `>>`) left in its text as `[brackets]`, trusts printed act/scene headings over model numbers.
  5. Flags are computed but not stored or shown: the parser still works them out with the six codes in `flags.ts` (the model writes `?? <code>`; a speech that carries on after a direction or page break without a new cue is never flagged), but `saveStructure` in `job.ts` saves every line unflagged. There is no script review; migration `012_no_review.sql` cleared older flags.
- Parser changes must be measured with the benchmark in `backend/bench/` (README there). Run the training fixtures at least twice; model output varies between runs. Holdout sets live outside the repo in `<workspace>/.codex/holdout*` and are only for first-try checks. They are kept data, not scratch: never move them into `.claude/tmp/`.
- Neon ignores a plain `search_path` startup parameter; `createSql` passes it through `options` instead.
- Audio sources: every dialogue line in a render uses its current take (the newest, by the cast actor or a director's stand-in), else a TTS clip, else silence. Timing entries carry `source` (`actor`, `standin`, `tts`, `none`). Progress, cast status, the actor-done email and cast completion count only takes with `recorded_by = 'actor'`; stand-ins and TTS never do. An actor's own `take` in `/api/invite/lines` is their latest own take, not a stand-in.
- Takes: `src/takes.ts` handles both uploads (`PUT /api/invite/lines/:lineId/take` for actors, `PUT /api/lines/:id/take` for directors in `src/routes/standin.ts`), with the same idempotency and caps per recorder. Stand-in takes have no `actor_id`; `recorded_by_user_id` holds the director. Normalizing a take cuts it to its speech (`src/render/trim.ts`): the noise floor and speech level come from the clip's own 10 ms frame levels, sound shorter than 40 ms (a tap or click) doesn't count, and 120 ms before / 200 ms after the speech are kept; nothing inside the speech is cut. Recordings then get a light clean-up (`highpass=f=70`, `afftdn=nr=10`, tracking the clip’s own noise floor; voices first, noise reduction second). Every clip, take or TTS, is levelled in two passes: loudnorm measures it, then one fixed gain to -16 LUFS (capped at ±30 dB) with a fast limiter at -1.5 dBFS, so all lines play at the same loudness (`level.test.ts`). The version is in the normalized key (`<take>.t3.flac`), so older takes are redone lazily on first use; TTS clips move to `TTS_SETTINGS.version` 3 the same way. Takes have no real length cap (65 min server safety net, the app stops at an hour); one bigger than a request (8 MB) arrives in parts (`X-Take-Parts`/`X-Take-Part`), staged in the temp folder and joined into the original file (`stagePart`); the web uploader sends takes over 6 MB that way (`sendInParts`).
- Shared lines (`src/shared.ts`, migration `011_shared_lines.sql`): a character named after others ("ANGELO, ESCALUS") or after the company (ALL, BOTH…) is a group, never a part; its lines carry `voice_ids`. The SQL function `sync_shared_lines` recomputes groups and voices; every route that changes a production's characters or lines calls `afterCastChange`. ALL lines start with everyone who speaks in the scene (`voices_source = 'scene'`), then `inferEnsembleVoices` asks Claude Haiku (effort low, `ctx.ensemble`) per scene who is on stage (`model`); a director's pick (`director`) wins and is never recomputed. The view `line_voices` (one row per voice) and `voice_take(line, shared, voice, actor_only)` drive progress, the call sheet and playback: each voice's newest take (its `takes.character_id`, or an actor take by whoever plays that voice). Two or more voice takes play as one mix (`render/mix.ts`, cached in `take_mixes` and storage by a hash of the takes). Takes are deleted by setting `deleted_at` (`setTakeDeleted`, which also moves `current_take_id` back); restore undoes it.
- TTS (`src/tts/`): Piper 1.2.0 (release `2023.11.14-2`) with `en_GB-cori-medium`, `en_GB-alan-medium` and `en_GB-vctk-medium` (16 English VCTK speakers), 18 voices in all, pinned with SHA-256 in the Dockerfile. `voices.ts` gives each character a voice from a hash of its id, in creation order, skipping voices already taken and never the narrator's (`NARRATOR_VOICE_ID`, VCTK p225, which reads stage directions in the run-through; bracketed directions inside dialogue are not read); title words in the name (QUEEN, LORD, LADY…) pick the gender. Clips are keyed by a hash of (engine, model, speaker, spoken text, normalization settings), normalized like takes, stored at `tts/<hash>.flac` (and `.m4a` for cues) and recorded in `tts_clips`, so only changed lines are synthesized again. `piper.ts` keeps a pool of `piper --json-input` processes (one model each, idle ones exit after a minute), `TTS_CONCURRENCY` + models − 1 of them (`pooledProcs`, 4 by default) so every model keeps a loaded process: with fewer, alternating speakers on different models reload a model for nearly every line, which stalled run-throughs at a new scene in production. Never pass `speaker_id` to a single-speaker model; Piper aborts.
- Without Piper (Windows dev) the probe logs once, `/health` reports `tts: null` (it never fails health) and lines render as silence with `source: "none"`. To try TTS locally, unzip `piper_windows_amd64.zip` from the same Piper release, download the three voices (`.onnx` and `.onnx.json`) into one folder, and set `PIPER_BIN` and `PIPER_VOICES_DIR`. Tests never need Piper: `createTestApp({ synthesizer: new FakeSynthesizer() })` from `src/test/tts.ts`, and TTS is off by default in tests.
- Cue audio: cues without a take get a TTS `.m4a`. `/api/invite` starts synthesizing the actor's cues in the background; the lines endpoints wait up to `TTS_CUE_WAIT_MS` for missing clips and return the rest with `audioUrl: null, audioSource: "none"` while they finish.
- Line-by-line playback (`src/linestream.ts`, `src/render/takeaudio.ts`): `GET …/lines/:lineId/audio` and `POST …/lines/audio/warm` (director and invite, see `docs/api.md`) return each line's own `.m4a`, so the player starts in about a second instead of waiting for the stitched render. Same source rules and cached files as the render: takes are normalized once into the FLAC the render uses plus a stream `.m4a` (`takes.stream_key`, one ffmpeg run), and every new TTS clip gets its `.m4a` (`cue_key`) beside its FLAC. `normalizeClip` reads clip lengths from the FLAC header instead of running ffprobe.
- TTS priority (`TTS_PRIORITY` in `src/tts/service.ts`): play > prefetch > cue > render, on a `PriorityPool`. Background work (cues, renders) gets at most `TTS_CONCURRENCY - 1` slots, so the stitched render runs one clip at a time with the default of 2; concurrent requests for one clip share one synthesis and raise its priority. Opening a run-through or asking for line audio prewarms Piper processes for the voices needed next (`prewarm`, only when the pool has room). Measured locally (Windows, warm Piper, render running): cold TTS line about 0.9–1.1 s to a playable URL, cached line about 0.17 s.
- Staleness: the render content hash includes each line's TTS clip hash. Opening a run-through queues the first render of a script, and rebuilds a finished render that is stale with nothing queued (a line edit, a TTS voice or engine change). Uploads still use the debounced queue.

- Env: `VITE_API_URL` (dev default `http://localhost:8080`, production builds default to `https://api.offbooked.com`). `VITE_STT_MODEL` picks the on-device speech model: `moonshine-tiny` (default), `whisper-tiny.en`, or `off`.
- Routes: `/` landing (with a playable demo voiced by the browser's speech synthesis), `/signin`, `/auth/verify?token=`, `/app` productions, `/app/new`, `/app/p/:id?tab=script|cast|play` (no `tab` opens the next step), `/app/p/:id/record?section=` director stand-in recording, `/join/:token` the whole-cast link, `/i/:token` actor welcome, recording and wrapped, `/i/:token/play` run-through (`?mode=mine` opens with the actor's lines on "Pause, then read").
- Look: calm and editorial, like a theatre programme. White page, Newsreader for headings (display optical sizes, weight 400–500, italic for scene titles and the odd flourish) and for script text, Hanken Grotesk for the interface and tracked uppercase micro-labels (`.eyebrow`, `.mono`), Google Fonts in `index.html`. `--font-mono` is a system monospace used only for the original's text in the source pane and the paste box. Soft neutrals, hairline borders (`--line`, `--line-strong`, `--edge`, `--edge-strong`) and soft shadows (`--shadow-sm`, `--shadow`, `--shadow-lg`); no hard ink outlines, offset shadows, tilts or stamps. One deep theatre red, used sparingly (`--accent`, a fill with white text; `--accent-text` for red text, `--accent-soft` for tints), and a warm ochre (`--sun`, `--marker`, `--flag-*`) for highlights. Radii 6/10/14px. `.raised` is a card with a soft shadow; `.btn-primary` is the one filled action on a screen, `.btn-secondary` the quiet outlined one. Confetti is a brief, muted fall of paper. Keep 44px targets and AA contrast, and respect reduced motion.
- Script text keeps its line breaks and indentation: anything that shows `Line.text` (review, cue lines, recording cards, run-through, editor) uses `white-space: pre-wrap`.
- Director flow: each production shows one next step (`routes/director/nextStep.ts`); once the script is read, that is sharing the cast link. Nothing asks the director to check or approve lines: the parse is taken as read. Script review is one continuous script page for reading and editing the script, with a sticky row holding "Share with the cast" and the scene jump (on a line, the arrows move up and down, E edits the text, Delete deletes), and editing in place (`LineEditor.tsx`): clicking a line's text makes that text editable where it stands (Enter or Ctrl+Enter saves, Shift+Enter is a new line, Escape cancels, leaving the field saves), and the open line's name slot becomes its controls: a type dropdown, a speaker dropdown for dialogue (with "New character…"), split, delete (one click, Undo puts it back through `POST /api/productions/:id/lines`) and close. [Bracketed] directions inside dialogue show in italics (`lineText.ts`). Hops scroll with `scrollToLine` (`reviewScroll.ts`), not `scrollIntoView`: it centres the line (with its editor when both fit) in the band between the sticky bars and the phone source sheet, keeps a nearby scene heading in view, jumps on long hops and re-measures until it lands, because sections use `content-visibility: auto` and change height as they render. Joining: hovering the break between two lines of a scene (or focusing it, or, on touch, the breaks around the open line) shows a "Join" control that names the speaker who keeps the text (the upper line). Splitting: while typing, the scissors split at the caret; otherwise they show the words to tap where the new line starts. The new line opens next. Every join and split has Undo (`lineJoin.ts` plans the undo: split at the old end and give the lower part its speaker back). The original sits beside it on wide screens and in a bottom sheet on phones (`SourcePane.tsx`): PDFs render with pdf.js (`PdfPage.tsx`, lazy loaded, fetched with the director header and range requests off) and the line is highlighted from the text layer; DOCX and text show `/script/source` with the line's source lines highlighted. Parse progress polls every 1.5 s.
- Cast: the cast link (`/join/:token`) is the only way people join, and the hero of the director's cast page. Below it are a read-only call sheet (`/call-sheet`: each part, who took it, lines recorded) and "Record a part yourself", which calls `record-as` and opens the normal actor recorder at `/i/<token>` as the director's own cast member. The cast page doesn't assign parts, make per-actor links or take emails and phones. The join page remembers the claimed invite per join link in localStorage (`offbooked.join.<token>`, `src/lib/joinMemory.ts`), so reopening it goes straight to `/i/<invite>`.
- Call sheet rows: the part's name opens its studio (`/app/p/:id/record?character=`, `SceneRecorder` in character mode: every line the part says across the play, with the cast's takes to play or delete and stand-ins to record; your own part opens your actor recorder instead), "n shared" counts lines said with others, and the row's ⋯ menu merges a duplicate part into another (`POST /api/characters/:id/merge`, likely duplicates from `duplicateCharacters.ts` first). The reset-link control sits quietly under the share button.
- Taking over: the call sheet's ⋯ menu also unassigns a part (`POST …/characters/:id/unassign`); what was recorded keeps playing. Actors pick up free parts with ＋ in the recorder header, on the wrapped screen, or when they have no lines left (`PickUpParts.tsx`, `GET`/`POST /api/invite/parts`). A line whose voice is someone else's take shows it as what plays now (`current`): an earlier cast member's take counts as done and has "Record over"; a stand-in still needs the actor.
- Intro: the first time a device opens a cast link (or a direct `/i/` invite before starting), `Onboarding.tsx` shows three short screens on how Offbooked works, with "Skip intro" and "I've used Offbooked before" always there. Seen or skipped once, it's remembered in localStorage (`offbooked.onboarded`).
- Shared lines in the app: script review shows a group's name (plus who says an ALL line); the speaker dropdown has "Several together…" (or "Who says ALL…"), a checklist that sends `voiceIds`. The recorder shows "with Queen" on a shared line and a "Play together" button once there are takes; "Hear partners" (dock option, `offbooked.hearPartners`) plays the cue before each take and the others' takes during a shared one (`useAccompaniment`). After a take, the take bar has play (with progress), Redo, Delete (Undo in the toast; toasts sit above the record dock) and the verdict chip. Actors fix their name from "as Riz ✎" in the recorder header (`PATCH /api/invite/me`).
- The director session token lives in localStorage (`offbooked.session`). Actor calls use the token from the URL.
- Takes are written to IndexedDB before upload and retried with backoff (`src/upload/`), keyed by a client UUID sent as `X-Take-Id`. Queue items have a `kind`: `invite` (actor takes, the default) or `director` (stand-in takes, `token` is the production ID). The actor recorder and the stand-in recorder share `audio/useTakeRecorder.ts`, `components/RecordDock.tsx` and `routes/actor/LineCard.tsx`.
- The run-through plays line by line, not the stitched render (`src/player/`): `queue.ts` plans the order (stage directions in the narrator's voice, the listener's own lines read, skipped or paused-then-read, the 350/1200 ms gaps and the prefetch window), `timing.ts` times the pause for one's own line (a take's trimmed length plus 15% or 0.5 s, else spoken words at 150 words a minute, at least 1 s), `settings.ts` keeps role, my-line mode and speed (other people's lines at 1–3×, `playbackRate` with pitch kept) per production in localStorage, `clips.ts` fetches each line's clip into a blob URL (falls back to the signed URL if the bucket refuses a cross-origin fetch), and `engine.ts` drives one `<audio>` element. Gaps, my-line pauses and the wait for a clip are silent WAVs played on that same element (`silence.ts`), so playback advances on `ended` events, not timers, and the play tap starts audio inside the gesture (iOS). The next 5 clips are downloaded and the next 25 lines warmed on the server; while a clip is missing the player shows "Getting the next line…" and asks for that line at play priority even if its prefetch is still out (a prefetch GET waits at most 8 s and isn't retried).
- Run-through layout and follow: the pinned row wraps on phones (the part picker always shows the name; the scene picker shrinks, then drops to its own row), and the page never scrolls sideways. While a line plays, `follow.ts` keeps the current word's row about 36% down the band between the pinned row and the player bar, gliding a row at a time on long speeches (reduced motion: the old comfort band and one jump). The original's sheet in script review re-centres its highlight when the line changes and whenever the pane appears or resizes (`useCentreHits` in `SourcePane.tsx`), until you scroll it yourself.
- Screen on: `audio/wakeLock.ts` (`useWakeLock(active)`) keeps the screen awake while a take records, while the run-through plays (gaps, my-line pauses and waits for a clip included) and while the landing demo plays. One shared `ScreenKeeper` counts holders, uses the Screen Wake Lock API, asks again when the browser drops the lock or the page shows again, and where the API is missing or refuses (iOS before 16.4, Low Power Mode, some webviews) plays `keep-awake.mp4`, a 2 KB muted inline looping video.
- The run-through marks each line's audio with a small tag from `RunThrough.sources`, updated as clips arrive (`TTS`, `stand-in`, `silent`; nothing for the cast's own takes).
- On-device accuracy (`src/stt/`, see `docs/on-device-stt.md`): transformers.js runs Moonshine Tiny (fp16 encoder, q8 decoder) in a module worker. One session per tab (`useStt.ts`) starts loading as soon as the cast link or `/i/:token` has loaded, so it is usually ready by the first take; takes never wait for it, and live word highlighting needs it. It is disposed 20 s after the last screen using it (join, welcome, recorder, practice) closes. The recorder chip shows real download progress ("Getting the accuracy check ready… 40%"). Model files are self-hosted under `/models/<dir>/` (immutable cache headers in `vercel.json`): `scripts/fetch-stt-model.mjs` downloads the files pinned in `src/stt/hosted-model.json` (revision and SHA-256) into `public/models/` (gitignored) before `npm run dev` and `npm run build`; change `dir` when a file changes. The plain ONNX Runtime WASM comes from the installed `onnxruntime-web` via Vite `?url`. No COOP/COEP headers. Takes show Complete, Partial or Not attempted (`verdict` in `score.ts`, from how many of the line's words were attempted, mishearings included), not percentages; the `accuracy` posted with a take is unchanged.
- Live words and auto-advance on the actor recorder (`stt/live.ts` pure logic with tests, `stt/useLiveTake.ts`, `audio/liveCapture.ts`): an AudioWorklet (from a blob URL) downsamples the open mic to 16 kHz while a take records. Once the speech model is ready, the hook re-transcribes the take in the same worker (the whole take up to 10 s, then the last 7 s; less when passes are slow), pacing passes at 1.25 × the last pass's latency (350 ms to 2 s), and `applyPass` aligns each transcript with the line (free start, free end, skips, mishearings, repeats, contractions, numbers; `[bracketed]` directions are never required and show muted) to move a monotonic "spoken up to" cursor. An energy VAD with an adaptive floor drives `decideAdvance`, which favours ending the take over judging it: once there has been real speech, a pause always stops the take, keeps it and moves on (and records the next line when "Keep recording" is on); it never holds a line. The cursor only sets the pause: 0.7 s once it is in the last 30% of the line; 1.5 s when the words weren't heard (or the transcript lags) but the actor has spoken at least 60% of the line's expected speech time (300 ms voiced per word); 3 s when the cursor is clearly mid-line (transcript current, heard words explain the speech, 2+ words left), so a pause for effect survives. Without the model (first take, unsupported device) there's no highlighting and the take stops after 1.5 s of silence once enough speech for the line was heard, 2.5 s after less. "Auto-advance" (on) and "Keep recording" (off) are dock checkboxes stored in localStorage (`offbooked.autoAdvance`, `offbooked.keepRecording`). Measured on a desktop CPU with Moonshine tiny: 60–300 ms per pass for 1–4 s of audio, 500–880 ms at 7–10 s; each take logs `[live stt] n passes, median, max` with `console.debug`. While a take records, the next word to say is followed karaoke style (`keepInView` with `recorderBand`): held near the middle of the band between the recorder header and the dock, never so low that fewer than three rows show beneath it (the run-through follows the same rule). A scroll by hand pauses it for 2.5 s. The capture keeps only the last 30 s of samples, so long takes stay small. An actor with several parts records one at a time: chips under the header switch parts (`offbooked.part.<token>`), picking up a part shows it, and the run-through opens on that part (`?part=`).
- `web/vercel.json` rewrites every non-asset path to `index.html`. The mic is only requested from a record tap, never on load.

## Product rules that shape the code

- Actor invite links are shared by the director (copy link or the native share sheet). The app does not email or text invites or reminders.
- Email (Resend) is only for completion notifications: an actor finished all their lines, the cast is complete, the run-through is ready.
- Recordings are kept forever for now. Nothing deletes audio objects, including re-records, deleted takes (hidden with `deleted_at`, restorable) and production deletion.
- Actors have no accounts. Their invite token is their only credential and is scoped to their own lines plus cue context.
