# The iOS app

Offbooked's iOS app is the web app in `web/`, bundled into a native shell with [Capacitor](https://capacitorjs.com) 8, plus a few things only an app can do. The web cast link stays the front door: nobody needs the app, and every link still works in Safari. The app is for people who use Offbooked a lot, mainly cast members running lines with the screen off. Android comes later (`npx cap add android`).

Everything builds on GitHub's macOS runners (`.github/workflows/ios.yml`). Nobody needs a Mac to build, sign or ship it. The short [Mac checklist](#mac-checklist) at the end covers the few things that do need one.

## Architecture

```
┌──────────────────────── iPhone ─────────────────────────┐
│  Offbooked.app (com.offbooked.app)                      │
│  ┌───────────────────────────────────────────────────┐  │
│  │ WKWebView at capacitor://localhost                │  │
│  │   web/dist, bundled at build time (never a remote │  │
│  │   server.url), incl. the speech model (/models)   │  │
│  │   src/native/*  ── Capacitor bridge ──┐           │  │
│  └───────────────────────────────────────┼───────────┘  │
│  MainViewController (web view below the status bar)     │
│  OffbookedNativePlugin.swift  ◄──────────┘              │
│    audio session, Now Playing, lock-screen commands,    │
│    background time for uploads                          │
│  @capacitor/app (links, resume), /network, /filesystem  │
└───────────────┬─────────────────────────────────────────┘
                │ fetch, Authorization header (no cookies)
                ▼
     https://api.offbooked.com (Railway), unchanged
```

- `web/capacitor.config.ts`: app id `com.offbooked.app`, `webDir: "dist"`. There is deliberately no `server.url`: a shell that loads offbooked.com is what App Review rejects under guideline 4.2, and the bundled app also opens without a connection.
- `web/ios/`: the Xcode project. It uses Swift Package Manager (`ios/App/CapApp-SPM/Package.swift`, regenerated by `npx cap sync ios`), so there is no CocoaPods and no `pod install`. `ios/App/App/public` (the copied web build) and `capacitor.config.json` are generated and git-ignored.
- The API is the production API, `https://api.offbooked.com` (the production default of `VITE_API_URL`). The backend always allows the app's origin, `capacitor://localhost` (`NATIVE_APP_ORIGINS` in `backend/src/app.ts`), whatever `CORS_ORIGINS` says. Auth is the director's bearer token in the web view's localStorage and the cast's invite token in the URL, the same as on the web.
- `src/native/platform.ts` (`isNativeApp()`) is the one switch between app and website. On the website none of the native code runs.
- Line clips are downloaded into blob URLs where the storage bucket's CORS allows the origin, otherwise played from their signed URLs (`player/clips.ts` already falls back). Adding `capacitor://localhost` to the bucket's CORS rules makes the app prefetch like the website does; it plays either way.

### What is native, and why (guideline 4.2)

1. **The run-through keeps playing with the screen locked**, with play, pause, next and previous on the lock screen, in Control Center and on headphones. `Info.plist` has the `audio` background mode; `OffbookedNativePlugin.setNowPlaying` puts the audio session in `.playback` (spoken audio, so it plays through the silent switch), fills `MPNowPlayingInfoCenter` (line, production, scene) and routes `MPRemoteCommandCenter` commands back to the player engine. In the web code this is `native/nowPlaying.ts`; on the website the same calls use the Media Session API.
2. **Takes are saved on the phone and upload when there is a connection.** The recorder is the web one (it has to be: live word following and auto-advance run on the open mic stream), but takes waiting to upload are files in the app's `Library/offbooked-takes/` (`native/fileTakeStore.ts`), not the web view's IndexedDB, which iOS may clear when storage runs low. The uploader is the website's (`upload/uploader.ts`: one take at a time, backoff, never gives up), resumed when iOS reports the network is back (`@capacitor/network`) and whenever the app returns to the front. While a take is sending, the app asks iOS for background time so it can finish if the phone is locked mid-upload. Recordings cross the Capacitor bridge as base64; that is fine for ordinary takes, but an hour-long take (60–80 MB of base64) is untested on a device and is the first thing to check if very long takes stop uploading in the app.
3. **Cast and sign-in links open the app** (universal links). `web/public/.well-known/apple-app-site-association` claims `/join/*`, `/i/*`, and `/auth/verify?app=1`. Sign-in links only carry `app=1` when they were asked for from the app (`POST /api/auth/request` with `app: true`), so a director who signs in from Safari stays in Safari even with the app installed. `native/NativeLinks.tsx` routes an opened link to its page; `offbooked://join/<token>` does the same (used by CI). Without the app, every link opens the website as before.
4. The app opens on its own home screen (`native/NativeHome.tsx`: paste a cast link, or sign in) instead of the website's marketing page.

The web app's microphone request is granted inside the app by Capacitor; iOS asks once, with `NSMicrophoneUsageDescription`.

## CI

`.github/workflows/ios.yml` runs on GitHub's standard macOS runners (`macos-latest`, free for this public repo; never a larger runner). It is not part of `ci.yml`: the full gate there (lint, types, tests with coverage, build, e2e, audit, secrets) already covers the web and backend code this app uses.

### simulator (every PR into `main` touching `web/`)

1. `npm ci`, `npm run build` (the production build, with the speech model), `npx cap sync ios`.
2. Picks an iPhone on the newest iOS runtime (`.github/scripts/pick-simulator.mjs`) and builds the Debug app for the simulator with `CODE_SIGNING_ALLOWED=NO`.
3. Boots the simulator, installs and launches the app, and fails unless it is still running after 25 s, Capacitor logged `Loading app at capacitor://localhost`, and the web console logged no errors (`console.log` in the artifact).
4. Opens `offbooked://join/not-a-real-link`: the screenshot shows iOS offering to open it in Offbooked (simctl can't tap Open), which proves the scheme is registered and the app keeps running. Where a link lands inside the app is covered by `src/native/links.test.ts`; universal links need a phone and the real Team ID.
5. Uploads `ios-simulator` (screenshots `launch.png`, `join-link.png`, the app's console and system log, the xcodebuild log) and `ios-simulator-app` (the built `.app`, zipped, for the Mac checklist).

To iterate from Windows: push, then `gh run list --branch <branch> --workflow iOS`, `gh run view <id> --log-failed` and `gh run download <id> -n ios-simulator`.

### testflight (manual, and on push to `main` once switched on)

Archives a Release build, signs it with automatic signing through an App Store Connect API key (`xcodebuild -allowProvisioningUpdates -authenticationKey…`, so Apple manages the distribution certificate and profile in the cloud and no certificate is ever exported), and uploads it to App Store Connect (`web/ios/ExportOptions.plist`, `destination: upload`). The build number is the run's UTC time (`yymmddHHMM`), so it only ever goes up; the version is `MARKETING_VERSION` in the Xcode project (1.0).

- Run it by hand: Actions → iOS → Run workflow → tick "Archive and upload to TestFlight". Or `gh workflow run ios.yml --ref main -f testflight=true`.
- On every push to `main`: set the repository variable `TESTFLIGHT_ON_MAIN` to `true` when TestFlight builds should follow production releases.
- With any secret missing, the job prints a notice naming them and skips every step (green, nothing uploaded).

### Secrets (repository → Settings → Secrets and variables → Actions)

| Secret | What |
| --- | --- |
| `APPLE_TEAM_ID` | The 10-character Team ID (developer.apple.com → Membership). |
| `ASC_KEY_ID` | The App Store Connect API key's Key ID (App Store Connect → Users and Access → Integrations → App Store Connect API, a Team key). |
| `ASC_ISSUER_ID` | The Issuer ID shown above the keys on the same page. |
| `ASC_KEY_P8` | The whole contents of the downloaded `AuthKey_<KeyID>.p8`, including the `BEGIN`/`END` lines. |

The key needs the **Admin** role: automatic signing from CI creates the cloud-managed distribution certificate and the App Store profile, which other roles can't. Before the first upload, the app record must exist in App Store Connect with bundle id `com.offbooked.app` (and the bundle id registered, which the first archive does itself if it isn't).

### Before the first TestFlight build

- **Team ID in the site association.** Replace `TEAMID` in `web/public/.well-known/apple-app-site-association` with the real Team ID, ship it to production (it's served from offbooked.com), and check `https://offbooked.com/.well-known/apple-app-site-association` returns it as JSON. Until then universal links don't open the app (everything still opens in Safari, and `offbooked://` works).
- **Associated Domains.** The entitlement (`ios/App/App/App.entitlements`: `applinks:offbooked.com`) should be enabled on the App ID by automatic signing on the first archive. If the archive fails with a provisioning error about Associated Domains, enable it once on developer.apple.com → Identifiers → com.offbooked.app.

## App Review readiness

- **Account deletion (5.1.1(v))**: directors have accounts (email sign-in links); "Delete my account" on `/app/account` calls `DELETE /api/me`, which signs the account out everywhere and clears its email, name, production titles and cast details at once, then deletes every production's script, recordings and renders (`deleteAccount` in `backend/src/retention.ts`; if storage fails part-way, the retention worker finishes the job). Cast members have no accounts; their recordings go with the production, by retention or with the director's account.
- **Sign in with Apple** isn't required: there is no third-party login, only email links.
- **Privacy**: `ios/App/App/PrivacyInfo.xcprivacy` (no tracking; audio, email and name collected for app functionality; UserDefaults and file-timestamp API reasons). App Store Connect's App Privacy answers should match: Audio Data, Email Address and Name, linked to the user, used for App Functionality, not for tracking; no other data. Capacitor and its plugins ship their own manifests.
- **Microphone**: `NSMicrophoneUsageDescription` says what it's for.
- **Encryption**: `ITSAppUsesNonExemptEncryption` is false (HTTPS only), so no export compliance questions per build.
- **Icon**: the brand mark full-bleed on the accent red, 1024 px with no alpha (`Assets.xcassets/AppIcon.appiconset`); the splash is the mark on white.
- **Copy**: the website's landing page says "No app" and the FAQ says there's no app to install. Both stay true for the website (nobody needs the app), but reword them when the app launches.

### Reviewer demo plan

Reviewers can't receive a sign-in email, so the review notes lead with the part that needs no account:

1. Before submitting, the owner signs in on production as a dedicated reviewer director (say `review@offbooked.com`, an address the owner reads), sets up "App Review demo" with a short public-domain scene (the seed's Hamlet 1.2 is fine) and a final performance date a year out, and records a few lines as the director so the listen-through has real voices.
2. App Review Information → Notes: the production's cast link, and three steps: open the link (it opens the app), pick a part and record a line (the microphone prompt appears), then "Listen through the play" and lock the phone to hear it continue with lock-screen controls.
3. For the director side, attach a short screen recording of signing in, uploading a script, sharing the cast link and deleting an account (App Review accepts a demo video), and say that sign-in is by emailed link with no password.
4. If Review insists on signing in themselves, the fallback is a reviewer sign-in: a backend env pair (`REVIEW_EMAIL`, `REVIEW_CODE`) that lets that one address sign in with a fixed code, off by default. It isn't built; build it only if asked, since it's a standing credential.

## Analytics (not added)

There is no analytics today. If PostHog is added: initialise `posthog-js` in `web/src/main.tsx` (one key, autocapture off), capture product events where the next steps change (`routes/director/nextStep.ts`, a take kept in `upload/uploader.ts`, a listen-through started in `player/engine.ts`), tag events with `isNativeApp()` to compare app and web, and add `NSPrivacyCollectedDataTypeProductInteraction` (analytics purpose) to `PrivacyInfo.xcprivacy` and the App Privacy answers, plus the PostHog host to the site's policies.

## Working on it

```bash
cd web
npm run build && npx cap sync ios   # copy the web build into ios/App/App/public
npx cap add android                 # later: the Android project, next to ios/
```

Change the web app as usual; `cap sync` picks it up. Change native code in `ios/App/App/*.swift` (add new files to `App.xcodeproj` too). The app version is `MARKETING_VERSION` in `project.pbxproj`. Keep Capacitor's packages (`@capacitor/*`) on the same version.

## Mac checklist

Only for what CI and a TestFlight build on a phone can't do. A Claude session on the owner's Mac can run these; each needs Xcode (from the App Store) and the GitHub CLI signed in.

1. **Debug the web view with Safari's Web Inspector.**
   ```bash
   gh run download --repo NathanPannell/offbooked -n ios-simulator-app <run-id>   # from the latest iOS run on the branch
   unzip Offbooked-simulator.zip
   xcrun simctl boot "iPhone 17" 2>/dev/null; open -a Simulator
   xcrun simctl install booted App.app && xcrun simctl launch booted com.offbooked.app
   ```
   Then Safari → Settings → Advanced → "Show features for web developers", and Develop → Simulator → localhost. The console, network and storage tabs show the app as it runs (debug builds are inspectable). For a phone, plug it in, turn on Settings → Apps → Safari → Advanced → Web Inspector, and build the Debug app to it from Xcode (`open web/ios/App/App.xcodeproj` after `npm run build && npx cap sync ios`).
2. **Profile audio or memory with Instruments** if lock-screen playback stutters or the app is killed in the background: Xcode → Open Developer Tool → Instruments, attach to the app on a plugged-in phone.

Everything else is on a phone with the TestFlight build, no Mac: lock-screen playback and controls, the microphone prompt, a take recorded in airplane mode uploading after, cast links from Messages opening the app.
